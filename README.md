# IVE Korea — 리워드형 광고 플랫폼: 이상탐지 & 리스크 분석

![Python](https://img.shields.io/badge/Python-3670A0?style=for-the-badge&logo=python&logoColor=ffdd54) ![Pandas](https://img.shields.io/badge/pandas-150458?style=for-the-badge&logo=pandas&logoColor=white) ![Jupyter](https://img.shields.io/badge/Jupyter-F37626?style=for-the-badge&logo=jupyter&logoColor=white) ![Gemini](https://img.shields.io/badge/Gemini%202.0%20Flash-4285F4?style=for-the-badge&logo=googlegemini&logoColor=white)

한국의 리워드형 모바일 광고 플랫폼에서 발생한 **1,680만 건의 클릭 이벤트**와 **14개월치 시간 단위 성과 데이터**를 종단 분석했습니다. 가설 기반 부정클릭 탐지 파이프라인, 매체 단위 리스크 집계, 재무적 노출 금액 정량화, 그리고 플랫폼 최대 트래픽 이상 현상을 사후 확인이 아니라 실시간으로 잡아낼 수 있었을지에 대한 out-of-time 백테스트를 포함합니다.

**본 저장소는 작성자 개인의 기여 부분입니다** (데이터 통합부터 부정클릭 탐지·검증까지). 파이프라인 연속성을 위해 팀원이 구축한 매체 운영 및 도메인 광고 최적화 레이어도 포함되어 있으나, 작성자 본인의 작업이 아니므로 상대적으로 간단하게만 문서화했습니다.

## 한눈에 보기

| | |
|---|---|
| **목표** | 라벨링된 정답 데이터 없이 189개 매체 파트너의 광고 부정클릭 리스크를 탐지·정량화하고, 도출된 플래그가 사후 분석용이 아닌 운영상 실시간 탐지기로도 유효한지 검증 |
| **방법** | 5개 가설 기반 규칙형 이상탐지 프레임워크(클릭-전환 소요시간, IP당 기기 수, IP당 클릭 수, 집중도, 시간대 패턴) → 매체 단위 리스크 등급 → 급성/만성 유형 분류 → LLM 보조 도메인 분류 |
| **검증** | `unscored`(미평가) 카테고리를 명시한 14개월 히스토리 백테스트("정상"으로 조용히 편입시키지 않음); 3개 시나리오 임계값 민감도 테스트; 이전일자 롤링 베이스라인만 사용한 look-ahead bias 없는 out-of-time 알림 백테스트 |
| **결과** | 고신뢰 이상 클릭 639만 건(38.0%), 총 노출 금액 ₩260.7M(고신뢰 구간 ₩67.1M), 클린 트래픽 전환율 8.74% → 30.50% 회복, 상위 2개 매체가 고신뢰 노출의 75.5% 차지 |
| **기술** | Python, Pandas, NumPy, Gemini 2.0 Flash API (규칙+LLM 하이브리드 도메인 분류) |

## 이 프로젝트를 이렇게 설계한 이유

라벨링되지 않은 트래픽에 규칙 기반 이상탐지기를 적용하면 "639만 건의 부정클릭, ₩260M 손실"처럼 권위 있어 *보이지만* 실제 데이터가 뒷받침하는 것보다 과장된 숫자가 나올 수 있습니다. 여기에는 독립적으로 검증된 무효 트래픽 라벨이 없습니다 — 정산 거절 기록도, 수동 부정클릭 확인 절차도 없습니다. 이 프로젝트의 모든 주장은 그 사실에 맞춰져 있습니다:

| 사용하지 않은 표현 | 대신 사용한 표현 |
|---|---|
| 확인된 부정클릭 | 고신뢰 이상치 |
| 총 손실 | 재무적 노출 |
| 전환율 회복 | 남은 저위험 트래픽의 전환율 |
| 봇(bot) 증거 | 자동화와 일치하는 행동 패턴 |

이 프로젝트의 성과는 단순히 표현을 조심스럽게 다듬은 데 있는 것이 아니라, 분석 자체가 검증을 견뎌냈다는 데 있습니다. 두 가지 구조적 버그(행 단위 분류 우선순위 버그, 그리고 소스 단에는 적용되지 않았던 도메인 재라벨링 수정)는 전체 데이터셋에 대한 실제 재실행에서 코드가 만들어냈어야 할 값과 다른 숫자가 나왔기 때문에 발견할 수 있었습니다. 프로젝트 후반 단계의 회고 검증에서는 기저 필터가 여러 독립적인 실행에서 안정적임이 확인되면서, 프로젝트 자체의 초기 주장(`ads_order`와 광고 비활성 간의 상관관계) 하나를 스스로 철회하기도 했습니다. 틀렸다는 것을 인정하고 바로잡는 과정 자체가 이 저장소가 보여주고자 하는 부분입니다.

## 방법론

### 1. 무엇보다 먼저, 데이터 품질
- 모든 테이블에 비용 구조 순서 규칙과 명시적 음수 불가 검사를 적용
- `click_key` / `ads_idx` 유일성 검증, 모든 조인에 `merge(validate=...)` 사용 — 1,600만 행 규모의 병합 파이프라인에서 조용한 행 폭증(row explosion)은 잘못된 숫자를 만들어내는 가장 흔한 원인입니다
- 광고 카탈로그의 `9999-12-31`("종료일 미정") 센티널 값(전체의 96.7%)을 파싱 이전 문자열 단계에서 실제 날짜로 변환 — 일부 pandas 버전에서 조용히 `NaT`를 만들어낼 수 있는 Timestamp 범위 우회 방식 대신 사용
- 전환 여부는 `ctit`의 null 여부가 아니라 리워드 테이블 소속 여부로 정의 — 이번 데이터셋에서는 두 정의의 차이가 실제로 발생하지 않지만, 구조적으로 더 안전한 정의

### 2. 명시적으로 검증한 5가지 가설

| | 신호 | 논리 |
|---|---|---|
| H1 | 속도 | 해당 광고 유형의 중앙값 CTIT 대비 약 10% 이하로 빠른 전환은 사람이 하기엔 행동학적으로 비현실적 |
| H2 | 디바이스 팜 | 하나의 IP 뒤에 비정상적으로 많은 수의 기기가 있다면 에뮬레이터/디바이스 팜을 시사 |
| H3 | 클릭 팜 | 하나의 IP에서 비정상적으로 많은 클릭 볼륨은 스크립트 기반 반복 참여를 시사 |
| H4 | 집중도 | H1~H3가 성립한다면, 이상 트래픽은 균등하게 퍼지지 않고 특정 매체·광고 유형에 몰려야 함 |
| H5 | 시간 패턴 | 자동화된 트래픽은 사람의 활동 리듬(시간대, 평일/주말)을 따르지 않아야 함 |

### 3. 행 단위 분류
우선순위가 중요합니다: `outlier`(3개 신호 중 하나라도 극단 백분위수에 도달)를 가장 먼저 확인하고, 그다음 `abusing`(신호가 위험/경고 구간에 있는 경우), 그다음 `non_rewarded`(전환되지 않은 경우), 나머지는 `normal`로 처리합니다. `abusing`은 `non_rewarded`보다 *먼저* 확인해야 합니다 — 기기/클릭 수 신호는 전환 여부와 무관하게 적용되는 IP 단위 속성이므로, 비전환 여부를 먼저 확인하면 전환되지 않은 이상 클릭이 "그냥 전환 안 된 정상 클릭" 범주에 조용히 묻힐 수 있습니다.

### 4. 매체 단위 리스크 집계
클릭 단위 신호는 고신뢰·모니터링 구간 트래픽 비율을 기준으로 매체별 `critical / risky / warning / normal` 등급으로 집계됩니다. **매체 리스크 임계값은 휴리스틱**이며 표본 크기 보정 없이 원시 비율을 사용합니다 — 클릭 4건에 극단 비율 40%인 매체와 클릭 100만 건에 35%인 매체가 현재는 동일한 라벨을 받습니다(이는 조용히 무시된 것이 아니라 알려진 한계로 명시했습니다).

### 5. 14개월 히스토리 검증과 `unscored` 카테고리
8월의 리스크 라벨을 동일 매체의 지난 14개월 행동과 대조 검증했습니다. 8월 클릭 단위 탐지기가 평가하지 않은 매체는 `unscored`로 유지했습니다 — 이를 `normal`로 조용히 편입시키면 실제로 검증된 히스토리 데이터의 비중을 과소평가하게 됩니다.

### 6. 급성 vs. 만성 분류
모든 고위험 매체가 같은 유형의 문제는 아닙니다. 19개 위험/심각 매체 전체를 평균 비중과 최근 대비 히스토리 비율로 나누면 세 가지 뚜렷한 패턴이 드러납니다: **급성 침투** 1건(갑작스럽고 큰 폭의 상승 — 인시던트 대응 필요), **만성 고비중** 매체 2건(전체 기간 동안 구조적으로 크게 나타남 — 차단이 아니라 계약/요율 협의 필요), **만성 저비중** 매체 16건(일상적 모니터링 대상). 노출 금액이 가장 큰 매체는 급성이 아니라 만성으로 밝혀졌으며, 둘을 혼동했다면 잘못된 운영상 대응으로 이어졌을 것입니다.

### 7. 임계값 민감도
메인 파이프라인의 모든 임계값(CTIT 배수, 극단 백분위수)은 자연법칙이 아니라 하나의 선택입니다. 전수 그리드서치는 아니지만, 세 가지 일관된 시나리오를 통해 최고노출 매체의 *순위*가 3배 범위의 엄격도 변화에도 유지되는지 검증했습니다:

| 시나리오 | CTIT 배수 | 극단 백분위수 |
|---|---:|---:|
| 보수적 | ×0.05 | 99.95% |
| 기본 | ×0.10 | 99.90% |
| 공격적 | ×0.15 | 99.50% |

### 8. Out-of-time 알림 백테스트 — look-ahead bias 수정
위 모든 임계값은 탐지 대상 이상치를 포함하는 동일한 31일 구간에서 계산됩니다 — 사후적 발견에는 문제가 없지만, 운영용 탐지기라고 주장하기엔 부적절합니다. 이 섹션만큼은 예외입니다: **오직 이전 날짜만**을 사용한 30일 롤링 중앙값/MAD 베이스라인(`.rolling()` 전에 `.shift(1)`을 적용해 특정일의 값이 자기 자신의 베이스라인에 스며들지 않도록 함)을 이용해 "탐지 가능했는가"보다 더 예리한 질문을 던집니다 — 당시 시점에 실제로 사용 가능했던 정보만으로 *언제* 탐지 가능했을지를 묻습니다.

## 결과 (최종 검증 실행 기준)

| 지표 | 값 |
|---|---:|
| 분석 클릭 수 | 16,831,054 |
| 고신뢰 이상치 | 6,387,902건 (38.0%) |
| 모니터링 구간 | 7,782,515건 (46.2%) |
| 정상/비전환 저위험 | 811,565 + 1,849,072건 (15.8%) |
| 원시 플랫폼 전환율 → 저위험 트래픽 전환율 | 8.74% → 30.50% |
| 고신뢰 재무적 노출 | ₩67,083,271 |
| 모니터링 구간 재무적 노출 | ₩193,575,035 |
| 평가된 매체 수 | 189개 (심각 7 / 위험 12 / 경고 35 / 정상 135) |
| 노출 집중도 | 상위 2개 매체 = 고신뢰 노출의 75.5% |
| 매체 유형 | 급성 침투 1건, 만성 고비중 2건, 만성 저비중 16건 |
| 8월 탐지기가 평가하지 않은 매체(`unscored`) | 14개월 리포트 행의 12.6% |

**임계값 민감도:** 시나리오별로 플래그된 클릭 비중은 34.6%~51.6%로 변동하고, 가장 느슨한 설정에서는 심각 매체 수가 거의 두 배(7→12)로 늘어납니다 — 하지만 세 시나리오 모두에서 노출 금액 상위 4개 매체는 동일합니다. 정확한 물량은 임계값에 민감하지만, 최고위험 매체의 정체는 그렇지 않습니다.

**Out-of-time 백테스트:** 사전에 정의한 알림 규칙(클릭비중 z-score > 5 **그리고** 당일 전환율 z-score < −3)은 실제 이상 발생 시점을 포함해 단 한 번도 발동하지 않았습니다 — 있는 그대로 보고하는 진짜 null 결과입니다. 원인 분석 결과: 클릭비중 단독으로는 실제 사건의 육안상 정체(plateau)가 나타나기 하루 전에 이미 이상 임계값을 넘었지만, 해당 매체의 전환율 자체가 역사적으로 워낙 변동성이 커서 거의 완전한 붕괴조차 극단 z-score로 잡히지 않았습니다. **알림이 억제된 원인은 신호 부재가 아니라 AND 조건 결합 자체**였습니다 — 동일한 엄격한 임계값에서 비중 단독 규칙만 사용했다면 약 하루의 지연으로 탐지할 수 있었을 것입니다.

## 알려진 한계
- 독립적으로 검증된 무효 트래픽 정답 데이터가 없음 — 여기 모든 라벨은 확정된 판정이 아니라 플랫폼 자체 분포 대비 통계적 극단치임
- 메인 31일 파이프라인에는 look-ahead bias가 존재(out-of-time 백테스트가 유일한 예외)
- 도메인 라벨링(규칙+LLM 하이브리드)은 100개 광고 표본 검사(94% 일치)만 거쳤고 전수 감사는 아님
- 매체 리스크 비율에는 신뢰구간/표본 크기 보정이 없음
- Out-of-time 알림 설계는 매체 1개에 대해서만 검증되었고 플랫폼 전체는 아님

## 향후 과제
매체 리스크 신뢰구간(Wilson / Beta-Binomial 축소 추정), 클릭 간격 특성(inter-click interval), IP-디바이스 그래프 구조(연결요소 기반 디바이스 팜 탐지), 신호별 기여도/중복 분석, 매체 규모 대비 피어그룹 임계값, 그리고 클릭 단위가 아닌 매체×IP 단위에서의 규칙 기반 vs. 비지도학습(Isolation Forest) 비교 재설계.

## 개인 기여
데이터 통합, 데이터 품질 검증, 피처 엔지니어링, 부정클릭 탐지 파이프라인, 재무적 노출 정량화, 14개월 히스토리 검증, 급성/만성 분류, 임계값 민감도 분석, out-of-time 백테스트는 작성자 개인의 작업입니다. 매체 운영 관리와 도메인 광고 유형 최적화는 팀원이 구축했습니다.
